# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

声笺 (Local Recorder) — an Apple Silicon–only macOS app (macOS 14+) for near-real-time local speech transcription. A single-process Swift app: the SwiftUI front end and an in-process backend that runs MLX inference through mlx-swift (until 0.3.x a separate Python/MLX process did this; see `spikes/HANDOFF.md` and `docs/REFACTOR-MLX-SWIFT.md`). User-facing strings, error messages, and docs are in Simplified Chinese; keep new UI text and error messages consistent with that.

## Commands

```bash
./scripts/build.sh      # swift build -c release, compile the MLX Metal kernels, assemble dist/声笺.app, ad-hoc codesign
./scripts/package.sh    # verify signature, refuse if model weights are in the bundle, create dist/声笺-<ver>-arm64.dmg + .sha256
./scripts/build_metallib.sh  # (called by build.sh / verify_inprocess.sh) .build/metallib/mlx.metallib from the mlx-swift checkout
```

Building needs full Xcode with the Metal Toolchain component (`xcodebuild -downloadComponent MetalToolchain`): SwiftPM does not compile mlx-swift's Metal kernels, so `build_metallib.sh` compiles the JIT-mode kernel set in `.build/checkouts/mlx-swift/Source/Cmlx/mlx-generated/metal` with `xcrun metal` for macOS 14. Dependencies are pinned in `Package.swift`/`Package.resolved` (mlx-swift exact 0.32.2, mlx-swift-lm by revision, swift-transformers).

Tests (no models; mock servers need only the system `python3`):

```bash
./scripts/test_backend.sh        # BackendCore/Segmenter/VAD/planner/cache/config/download flow (port of the former Python tests)
./scripts/test_download.sh       # model downloader against tests/mock_hub_server.py; `hub <model_id> [--full]` checks a real cache in models/
./scripts/test_ai.sh             # AI client + API translation queue, against tests/mock_ai_server.py
./scripts/test_audio.sh          # file/system audio input conversion, EOF, stop/restart (no capture permissions needed)
./scripts/test_streaming_asr.sh  # streaming ASR WSS client, against tests/mock_streaming_asr_server.py
./scripts/test_livetranslate.sh  # LiveTranslate client + AppModel, against tests/mock_livetranslate_server.py
```

There is no XCTest target. Each Swift test script compiles an explicit list of sources plus one `tests/*Tests.swift` into a standalone `@main` executable with `swiftc` (mock servers are started by the script and passed in via env vars such as `RECORDER_MOCK_URL`). When Swift code under test gains a dependency on another source file, add that file to the script's `swiftc` line. `test_backend.sh` and `test_download.sh` compile all of `Sources/RecorderBackend/` with the `Cwebrtcvad` objects from `swift build --target Cwebrtcvad`. `test_livetranslate.sh` compiles every `Sources/Recorder/*.swift` except `RecorderApp.swift` and `LocalBackend.swift`, plus `Sources/RecorderBackend/` and `tests/LocalBackendStub.swift` (placeholder engines, no MLX); `AppModel` therefore imports `RecorderBackend` only under `#if canImport(RecorderBackend)`.

Real-model verification (needs Metal GPU and models cached in `models/` in the Hugging Face layout; writes JSON results into `docs/`):

```bash
./scripts/verify_inprocess.sh [asr|whisper|translate|pipeline]
```

`asr`/`whisper`/`translate` run single models through `RecorderVerify` (`docs/model-verification-swift.json`, `whisper-verification-swift.json`, `translation-verification-swift.json`). `pipeline` plays the fixtures in real time (20 ms frames) through `BackendCore` with the real engines: endpointing latency per final, ASR call counts, local translation per unit (same-language speech must be skipped), and a Qwen → Whisper → Qwen switch that must release the previous weights (`docs/pipeline-verification-swift.json`; exits non-zero on failed checks). The `docs/*-verification.json` files without `-swift` are the Python-era reference results.

Version bumps: the version string is hardcoded in `scripts/build.sh` (Info.plist `CFBundleShortVersionString`/`CFBundleVersion`), `scripts/package.sh` (DMG name, volume name, install notes), and `README.md`. `package.sh` refuses to overwrite an existing DMG of the same name. After replacing `assets/AppIcon.png`, run `python3 scripts/make_icon.py`.

## Architecture

**Targets** (`Package.swift`): `Recorder` (SwiftUI app) → `RecorderBackend` (plain Foundation + `Cwebrtcvad`; the backend semantics) and `RecorderEngines` (MLX engine adapters implementing the backend's `ASREngine`/`TranslatorEngine`) → `RecorderMLX` (model layer: Qwen3-ASR, Whisper, text generation, `MLXRuntime`). `RecorderVerify` is the real-model verification CLI. Cross-module API in `RecorderBackend`/`RecorderEngines` is `public`; keep it minimal.

**Single process.** `AppModel.launch()` gets a `BackendChannel` from `LocalBackend.makeChannel()` (`Sources/Recorder/LocalBackend.swift`): it points MLX at the bundled `Contents/Resources/mlx.metallib`, sets `ASRValidation.whisperAssets` to the bundled `Contents/Resources/whisper`, and creates `BackendCore(root: ~/Library/Application Support/LocalRecorder, …)` behind an `InProcessChannel`. Local model load, transcription and translation never touch the network; only explicit downloads do (the downloader honours `HF_ENDPOINT`). Model weights live in `<root>/models`, never in the signed bundle.

**Messages** (`InProcessChannel` ↔ `BackendCore`): the former socket protocol survives as dictionaries — every message carries `protocol_version: 1`. Audio is a payload of a 4-byte big-endian header length, a JSON header (`session_id`, `sequence`, `start_sample`, 16 kHz, mono, `s16le`), then raw PCM16; `InProcessChannel` caps buffered audio at 320 KB and drops chunks beyond that. Control commands are `hello`, `load` and `download` (with `role: "translator"` and a `translation` dict they target the translation model), `translation_settings` (`enabled` / `target_language` / `provider: local|api` / `api_profile`), `cancel_download`, `start` (optional validated `endpoint_mode` and `endpoint_silence_ms`, saved for subsequent sessions), `asr_stream_final` (sentence results of a streaming ASR session), `stop`, and `shutdown`. ASR `load` accepts `provider: api` in its config and an ephemeral `api_key` beside the config. Events are `status`, `config`, `partial`, `final` (carries `forced_cut`), `translator` (translator state plus the saved translation config), `translation` (per unit: `unit_id`, anchor `segment_id`, `revision`, `text`, `done`, `skipped`), `error`, and download `progress` (carries `role`; numbers are `NSNumber` so `as? Double`/`as? Int` both work). If you change a message, update `AppModel.handle`, `BackendCore`, `tests/BackendTests.swift` and `RecorderVerify`'s `Pipeline.swift`.

**Swift front end** (`Sources/Recorder/`):
- `AudioCapture` resamples microphone input to 16 kHz mono PCM16. `AdditionalAudioInput` reads audio files at their original pace with AVAudioFile or captures system audio with ScreenCaptureKit (audio output only). Both use `InputPCMConverter`; EOF flushes resampling and asks AppModel to finalize. Stop drains callbacks on the serial input queue before sending the backend stop command; stale system-start completions are generation-guarded. `scripts/test_audio.sh` checks file conversion, EOF, stop and restart without capture permissions.
- `AppModel` holds session and transcript state. `Transcript.translations` is keyed by backend unit id, and `rows` maps `session:segment` to a row, so translations that finish after a new session starts still land on their row. `AppModel.translationTargets` must match `Backend.translationTargets`.
- `RecorderApp` contains the views, menu bar, and settings; `SubtitleWindow` is the floating subtitle overlay; `TextExport` handles transcript export.
- `LiveTranslate` is a standalone mode that bypasses the local backend entirely: when enabled, the app shuts down the backend and streams audio over WSS to the fixed `qwen3.8-livetranslate-flash-realtime` model for cloud transcription + translation, disabling the other ASR/translation/AI entry points. Optional translated speech playback uses the same session (24 kHz mono PCM16); `LiveTranslateAudio.swift` decodes audio deltas and plays them through AVAudioEngine with bounded buffering. Audio transcript events feed the same subtitle rows; old configurations default to text-only. Its config lives in UserDefaults (`livetranslate.configuration.v1`), and its Keychain account is namespaced `livetranslate:<endpoint>`, separate from ASR and chat-completions credentials.
- The AI client (`AIClient`, `AIProfiles`, `AIWorkspace`) uses native HTTP. `APITranslationQueue` also reuses this client for finalized transcript translation when `TranslationConfig.provider` is `api`; `api_profile` selects a saved base URL. The backend persists these choices but never sees API keys or sends API requests. API mode unloads and bypasses the local translator. Queue callbacks use transcript IDs across sessions, and negative translation unit IDs are reserved for API output (`-1` API translation, `-2` LiveTranslate; local units are ≥ 1). It streams from OpenAI-compatible `/chat/completions` endpoints. It stores one JSON profile per normalized base URL under `LocalRecorder/AIProfiles`, API keys in the Keychain keyed by endpoint, and the current selection in UserDefaults.

**Backend** (`Sources/RecorderBackend/`, a line-by-line port of the former `backend/*.py`; error texts and state semantics are kept verbatim, `BackendError` carries the Python exception name so error events read the same):
- `BackendCore` (actor; was `server.py`): command dispatch and the state machine. One pump loop consumes `jobs` (`load` / `load_api` / `infer` / `finish` / translator load/unload) plus one `preview` slot. Final segments are always queued, but only the latest preview is kept, and it is dropped once its segment is finalized. If 6 or more final jobs are pending, it auto-stops recording. If audio `sequence`/`start_sample` values are non-contiguous, it flushes and raises an error. Heavy work (inference, loads, translation steps) is awaited off the actor, so control commands are never blocked by inference. Downloads run as one cancellable `Task` (`ModelDownloader`); only one download runs at a time, a cancelled or superseded download never reports back, and success queues a `load`. Explicit `load` paths (local directories, fresh downloads) are validated like cached ones.
- Translation shares that pump. Priority is `jobs` (ASR finals, loads, `finish`) > translation > preview. A running translation is a pull-based token stream (`MLXTranslatorEngine.stream`, one token per pull on the MLX queue); the pump stops pulling whenever `jobs` is non-empty and resumes later, and dropping the iterator releases the KV cache. Translator failures are reported through `translator` events and never change the ASR state or clear its queue. Enabling translation loads the translator, disabling unloads it, and a successful ASR load auto-loads it when enabled. At most 4 units wait; older ones are skipped with an overload error.
- `ConfigStore` (was `core.py` `Config`/`TranslationConfig`): strictly validated. `schema_version` is checked, unknown or out-of-range values raise `ValueError`-kind errors (JSON numbers are type-checked strictly), and `save` writes atomically with mode 0600. `config.json` is saved only after load and warmup succeed, so a failed switch keeps the previous config. `TranslationConfig` is saved to its own `translation.json`, so ASR and translator settings commit independently.
- `Segmenter` + `WebRTCVAD` (was `core.py` `Segmenter` + the webrtcvad wheel; the same WebRTC C sources are compiled as `Cwebrtcvad`): groups 20 ms frames with VAD (mode 2) into segments. Pre-roll is used only after silence. Default `endpoint_mode: smart` uses recognition feedback plus 500/1000/1800 ms silence thresholds; `fixed` uses `endpoint_silence_ms` (default 1000 ms). Explicit stop flushes immediately. `RecognitionCache` (was `recognition.py`) holds per-segment complete-chunk and whole-preview caches, cleared after final or model load/failure. No repeated previews are queued without new voiced samples. Internal voiced-position metadata never goes into events. Periodic previews remain provisional. `max_segment_seconds` only bounds each model input; it never forces a final. Final segments are contiguous and non-overlapping by design: there is no text dedup, so repeated words the speaker really said are kept. Don't add overlap or dedup. Current finals carry `forced_cut: false`; the field remains for compatibility.
- `TranslationPlanner` (was `translation.py`): turns finals into translation units. A silence-ended final is one unit. Legacy forced-cut handling is retained: after a forced cut, the last sentence carries into the next final with its trailing punctuation removed, because Qwen3-ASR punctuates cut-off audio as if the sentence had ended. `TranslationText.alreadyInTarget` skips same-script text before generation; `sameText` hides output identical to the source; `buildMessages` holds the prompts (Hunyuan-MT single-turn, others system + 2 context pairs). `validateTranslator` mirrors the ASR checks: an architecture allowlist, no `auto_map`, and a required chat template.
- `ASRValidation` (was `adapter.py` `validate_config`): detects the architecture from `config.json` (MLX Qwen3-ASR or MLX Whisper; Transformers/PyTorch formats are rejected) and checks the bundled Whisper assets. The engines (`Sources/RecorderEngines/`) hold one model at a time; all MLX work is serialized on `MLXRuntime`'s queue, and unloading clears the MLX cache.
- `ASRAPIClient` (was `asr_api.py`) sends bounded WAV speech chunks to a configured OpenAI-compatible `/audio/transcriptions` endpoint. The Swift UI stores its API key in Keychain; the backend receives it only in the `load` command and keeps it in memory. Saved `Config` contains the provider, base URL, and model ID, but no key. Redirects are rejected. The existing recognition cache, segmenter, and final/partial event flow are shared with local ASR.
- ASR `api_protocol: qwen_realtime` (a historical tag; the UI calls it "WebSocket 调用") is streaming recognition with a fixed model (`qwen-audio-3.0-asr-flash-streaming`) and fixed endpoint (`StreamingASRConfiguration`; only the API key is user-configurable, Keychain account `StreamingASRConfiguration.keyAccount`) over the DashScope duplex protocol (`/api-ws/v1/inference`: `run-task` → `task-started` → binary PCM → `result-generated` → `finish-task` → `task-finished`/`task-failed`). `StreamingASRClient` runs in the app with the Keychain key; audio goes from capture straight to it (coalesced into ~100 ms frames), never to the backend. The cloud task starts before the backend `start`; `sentence_end: false` results are shown as `partial` locally, and sentence ends are sent to the backend as `asr_stream_final` (`segment_id` = `sentence_id`, `start_sample`), which the pump republishes as a normal `final` and plans for translation. Stop sends `finish-task`, and the backend `stop` is sent only after `task-finished`, so late sentences still land. In streaming sessions the backend has no segmenter and rejects audio frames. `AppModel.migrateLegacyStreamingConfig` rewrites saved configs with any other address or model (e.g. the former `/api-ws/v1/realtime` chat endpoint) to the fixed values and copies their key. `scripts/test_streaming_asr.sh` tests the client with a local fixture; `BackendTests` tests `asr_stream_final`.
- `ModelCache` (was `model_cache.py`) resolves HF-cache snapshots under `<root>/models` with a role-specific `validate` callback: an explicit revision must exist (hard error), otherwise `refs/main`, then an mtime scan. With no saved config the app resolves the newest valid cached snapshot (the Python builds pinned it through `initial-config.json`).
- `ModelDownloader` (was `download.py`) writes the huggingface_hub cache layout directly: `blobs/<sha256 or git blob id>`, relative `snapshots/<sha>/` symlinks, no `refs/` for SHA revisions, `CACHEDIR.TAG`. It keeps download.py's extension filter, which must include `.jinja` or translation models lose their chat template. Partial LFS blobs (`.incomplete`) resume with a Range request; every file is checked against its sha256 / git blob id before it is moved into place. Caches written by the Python builds and by this downloader are interchangeable.

**Model layer** (`Sources/RecorderMLX/`): `Qwen3ASR` (model, mel front end, BPE tokenizer), `Whisper` (mlx-whisper 0.4.3's transcribe path: fp16, temperature 0, timestamp rules, no-speech skip; its mel filters and tiktoken vocabularies are vendored in `assets/whisper/` and bundled by `build.sh`), `NPZ` (numpy archive reader), `MLXTextGenerator` (mlx-swift-lm + a swift-transformers tokenizer bridge; Qwen3 chat templates get `enable_thinking: false`). Porting lessons (weight loading with `NestedItem.unflattened` + `.noUnusedKeys`, mel numerics) are in `docs/SPIKE-RESULTS.md`.

**Invariants to preserve:**
- Model weights never go in the app bundle (`package.sh` enforces this).
- Local model load, local transcription, and local translation stay offline; explicit downloads, API transcription, LiveTranslate, AI requests, and enabled API translation use the network.
- Raw audio and transcript history are never persisted (`Config` rejects `save_audio`).
- The settings directory and model cache layout stay compatible with existing installs (`config.json`, `translation.json`, `models/models--<owner>--<model>/snapshots/<sha>`).
- Dependencies are pinned (`Package.resolved`, mlx-swift exact version matching the compiled kernels), and nothing is installed at runtime.

Release notes and verification history are in `docs/RELEASE-*.md` and `docs/VALIDATION.md`.
